# Разработка

Изменения должны сохранять происхождение данных, историю наблюдений и неизменность уже выпущенных отчётов. Используйте синтетические примеры в тестах, issue и скриншотах; рабочие документы и `.env` не коммитьте.

## Окружение

Рекомендуется Python 3.12, PostgreSQL 17 и Node.js 22. Для запуска приложения используйте [Docker Compose](docs/install-windows.md). Для разработки интерфейса установите инструменты из корня репозитория:

```sh
npm ci
python -m pip install -r requirements-dev.txt
```

Для локальных команд Django задайте `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_HOST`, `POSTGRES_PORT` и `DJANGO_SECRET_KEY` в окружении процесса. Файл `.env` автоматически читает Compose; обычный запуск Python не загружает его сам.

## Проверки

```sh
python manage.py check
python manage.py makemigrations --check --dry-run
python manage.py test tests --noinput
npm run check
djlint templates --check
```

Django создаёт отдельную тестовую базу. Тестовая роль PostgreSQL должна иметь право `CREATEDB`; проверки запускайте вне рабочего экземпляра с производственными данными. В Compose аналогичные Python-команды выполняются через `docker compose exec web python manage.py ...`.

Перед коммитом отформатируйте изменённые файлы:

```sh
npm run format
djlint templates --reformat
```

Форматирование и CSS проверяются конфигурацией проекта. В интерфейсе используйте общие токены цветов, размеров и отступов, SVG-спрайт и доступные подписи. Основной текст должен оставаться читаемым на мобильном экране; диаграмма сопровождается таблицей значений.

## Изменения и отчёт о проверке

- Описывайте конкретный сценарий и ожидаемый результат.
- Миграции включайте в тот же набор изменений, что и модель.
- Содержательные изменения покрывайте тестом; для оформления проверяйте реальный экран, контраст и клавиатуру.
- При изменении источника отдельно указывайте проверку на сохранённом файле и реальную загрузку из сети.
- Для нового поведения обновляйте соответствующую инструкцию и `CHANGELOG.md`.

GitHub Actions выполняет проверки на push и pull request. Условия лицензирования кода остаются решением владельца проекта.
