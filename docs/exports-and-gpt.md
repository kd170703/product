# Выгрузки и панель GPT

## Зафиксированные отчёты

Вкладка отчётов получает тот же отфильтрованный список наблюдений, что и таблица приложения. Экспорт не выполняет независимый запрос к источникам и не пересчитывает неизвестные числители. Word и Excel формируются из одного JSON-снимка, который содержит фильтры, значения, состояния данных, версии наблюдений, ручные поправки (если они применены), сведения об источниках, дату формирования и полные определения версий методик и формул.

Для снимка вычисляется SHA-256. Готовые DOCX и XLSX сохраняются в файловом хранилище приложения; скачивание ранее выпущенного отчёта возвращает готовый файл. Новая загрузка данных создаёт новую версию наблюдения, но не изменяет выпущенный отчёт. Резервная копия должна включать PostgreSQL **и** каталог `media`, содержащий отчёты и исходные публикации.

Структура Word повторяет приложенную сводную форму: альбомный лист A4, одна основная таблица из трёх параллельных колонок. Слева — блок социологических исследований, в центре — статистические показатели, справа — финансовый тест с количеством прохождений и опубликованным процентом верных ответов. Каждая из 13 тем начинается объединённой строкой на всю ширину; затем повторяются названия трёх блоков. Вопрос, варианты ответов, значения разных периодов и ссылки находятся внутри соответствующей ячейки. Ширина колонок и поля страницы соответствуют пропорциям образца. Таблица полностью редактируема, без заливки; основной шрифт Times New Roman 14.

В одной ячейке социологии показаны ответы на один вопрос по соответствующим волнам. Статистика группирует ряд одного показателя по периодам; финтест показывает формат «период — количество / опубликованная доля». Округлённый процент не используется для восстановления количества правильных ответов. Размещение записей рядом сохраняет общий тематический контекст; числа в разных колонках не складываются.

ИРФК и онлайн-зачёт, отсутствующие в исходной форме, приведены после основной таблицы как дополнительные разделы. Диаграммы вынесены в отдельное приложение, поэтому основной отчёт сохраняет вид трёхколоночной сводной таблицы. При нескольких сопоставимых периодах строится динамика; разные ответы остаются отдельными рядами. В обзорном приложении Word показано до двух диаграмм на тематический блок, а все отфильтрованные значения остаются в таблице и Excel. Для просмотра остальных рядов используется конструктор диаграмм приложения.

Прямые официальные ссылки сохраняются как гиперссылки. Для загруженного файла указываются имя, лист, ячейки или страница. После таблицы и диаграмм приведены источники, версии и содержательные примечания к расхождениям. Прежние служебные отметки о незавершённой проверке не печатаются в отчёте и Excel; история происхождения и версий сохраняется в базе и снимке. Конфликтующие значения не подменяются другим источником автоматически.

Числовой ноль, отсутствие данных и неприменимость различаются. В Excel для отсутствующего/неприменимого значения числовая ячейка пуста, а отдельный столбец содержит состояние; числа и даты сохраняются в собственных типах Excel. Разные единицы не складываются. Одна запись может присутствовать под несколькими тематическими рубриками Word, сохраняя один ID и одну версию; лист «Наблюдения» Excel содержит по одной строке на наблюдение.

## GPT: предложение с подтверждением

Настройте на сервере `OPENAI_API_KEY` и `OPENAI_MODEL`. Ключ не передаётся в шаблоны, браузер или выгрузки. Если ключ или модель не настроены, только панель GPT сообщает о необходимости настройки; импорт, ручной ввод и отчёты работают самостоятельно.

Поддерживаются DOCX, XLSX, PDF с текстовым слоем, TXT, CSV, JSON и Markdown. Ограничения: 20 МБ на файл, 80 МБ распакованного Office-документа, 120 000 символов извлечённого текста, 300 предложений в одном ответе. Для сканированного PDF требуется предварительное OCR. Формулы Excel передаются как формулы, не исполняются; процентный формат ячейки отображается кодом приложения.

Приложение отправляет текст документа, инструкцию сотрудника и справочник показателей в OpenAI Responses API со строгой JSON-схемой, без инструментов и без автоматической записи. В запросе задано `store=False`. Документ рассматривается как недоверенный текст. API не получает инструмента исполнения кода и доступа к базе. Секреты сервера в запрос не включаются.

Локальная проверка отклоняет неверные числа, даты, состояния и опасные схемы URL. Несопоставленные коды, несовпадающие единицы, пустые обязательные поля и неоднозначности помечаются для проверки. Предложения сохраняются отдельно от наблюдений; фактическая запись выполняется после явного подтверждения через обычный импорт приложения с проверкой прав. Арифметика и методические расчёты остаются в программном коде. По округлённым процентам точные количества правильных ответов не восстанавливаются.

## Проверки

`tests/test_exports_gpt.py` содержит проверки структуры и содержимого Word/Excel, различения нуля и пропуска, ссылок, снимков версий, защиты от формул в Excel и локальной валидации GPT. API в тесте заменён заглушкой. Успешный тест заглушки **не означает** проверенный реальный вызов OpenAI. Для живой проверки требуется ключ с доступом к выбранной модели и сети; её результат следует фиксировать отдельно.
