# Готовые образы для сервера

GitHub Actions проверяет Python-код, миграции, шаблоны и оформление. Только после
успешного задания `check` в основной ветке задание `publish` собирает и публикует
два образа в GitHub Container Registry:

| Назначение | Образ |
| --- | --- |
| Веб-приложение и фоновый процесс | `ghcr.io/kd170703/product` |
| Ежедневное резервное копирование | `ghcr.io/kd170703/product-backup` |

CI отдельно проверяет production-конфигурацию Compose и Caddy. Собранные образы
затем запускаются по digest в изолированном тестовом проекте: проверяются отказ
без `SECRET_KEY`, запуск веб-сервиса и фоновых процессов, параметры HTTPS и 2FA,
автоматическое создание первой копии и восстановление синтетической базы и
файла. Теги `main` обновляются после этих проверок. Сетевой выпуск настоящего
TLS-сертификата и доступность сервера организации проверяются при развёртывании.

Публикация запускается при `push` в `main` и при ручном запуске CI для `main`.
Pull request выполняет проверки, но не получает задание публикации. Для форка
публикация отключена: владелец должен сначала изменить имена образов и условие
репозитория в workflow. Отдельный ключ для публикации не нужен: используется
короткоживущий `GITHUB_TOKEN` с правом `packages: write` только в задании публикации.

Сборка рассчитана на Linux x86-64 (`linux/amd64`). Запуск на ARM-серверах пока
не проверен; перед такой установкой нужно добавить и проверить ARM-сборку.

## Первое получение образов

Первый опубликованный пакет GHCR может оказаться **приватным**, даже если сам
репозиторий публичный. Владелец выбирает один из вариантов:

- Для публичного пакета разрешить публичное чтение в настройках соответствующего
  GitHub Package. В образах находятся код и зависимости; рабочие данные, файлы
  сотрудников, настройки и секреты в контекст сборки не входят.
- Для приватного пакета дать серверной учётной записи право чтения пакетов. На
  сервере выполнить `docker login ghcr.io -u ИМЯ_УЧЕТНОЙ_ЗАПИСИ` и ввести токен
  чтения пакетов в запросе пароля. Не помещать токен в `.env.prod`, репозиторий
  или командную строку. Для личного токена GHCR обычно нужен classic PAT с
  `read:packages`; в организации могут потребоваться SSO и отдельное разрешение.

Настройка видимости и политик организации требует прав владельца. Сам факт
наличия workflow не означает, что пакет уже опубликован: проверьте зелёное
задание `publish` и вкладку Packages репозитория.

## Выбор версии

Каждая успешная публикация получает теги `main` и `sha-<полный SHA коммита>`.
`main` удобен для знакомства, но меняется при новых публикациях. Для рабочего
сервера укажите **один и тот же SHA** у приложения и службы копирования в
`.env.prod`:

```dotenv
APP_IMAGE=ghcr.io/kd170703/product:sha-ПОЛНЫЙ_SHA_КОММИТА
BACKUP_IMAGE=ghcr.io/kd170703/product-backup:sha-ПОЛНЫЙ_SHA_КОММИТА
```

В Summary успешного CI приведена готовая пара ссылок с SHA и с digest.
Фиксация `@sha256:…` также поддерживается Compose и исключает изменение
содержимого образа по тегу. Считайте выпуск готовым после завершения обоих шагов
публикации; частично завершённый или отменённый запуск не является выпуском.

## Обновление сервера

Первичная настройка описана в [инструкции сервера](server-deployment.md).
После выбора проверенной версии сервер загружает готовые образы без локальной
сборки Python и Docker-образов:

```sh
docker compose --env-file .env.prod -f compose.prod.yaml pull
docker compose --env-file .env.prod -f compose.prod.yaml up -d
```

Перед обновлением сохраните резервную копию и текущие ссылки на образы.
Проверьте журнал миграций и состояние сервисов после запуска. Возврат старого
образа не отменяет миграции базы; если миграция несовместима, нужен согласованный
план восстановления базы и файлов. Не восстанавливайте старую базу поверх
новых данных без решения ответственного администратора.

## Граница между сборкой и рабочими данными

В `.dockerignore` исключены `.env*`, `.secrets`, `media`, `data`, `incoming`,
`backups`, `backups-prod`, рабочие каталоги и исходные документы Word/Excel/PDF.
Секреты передаются контейнерам при запуске через файлы Docker Compose secrets;
GitHub Actions они не нужны. Публичные скриншоты содержат демонстрационные данные.
Не меняйте исключения ради включения реестра, резервной копии или настроек в образ.

Загрузка кода из GHCR не размещает рабочую базу на GitHub: базой, файлами,
журналами и резервными копиями управляет сервер организации. Их фактическое
местонахождение и доступы проверяются отдельно перед вводом в эксплуатацию.
