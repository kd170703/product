# Развёртывание и эксплуатация

Основная схема для сервера организации — готовые образы, Caddy, PostgreSQL и отдельные процессы обновления и резервного копирования.

- [Серверный запуск и HTTPS](server-deployment.md): compose.prod.yaml, секреты, домен, обновление без сборки.
- [Образы GitHub Container Registry](image-publishing.md): CI, вход в реестр и фиксация версии.
- [Безопасность входа](security.md): ограничение попыток, TOTP и восстановление доступа.
- [Ежедневные зашифрованные копии](backups.md): расписание и восстановление.
- [Размещение данных в России](data-localization.md): инфраструктура и решения оператора.

Для локальной работы используется compose.yaml: [установка в Windows](install-windows.md), [эксплуатация локальной установки](operations.md), [корпоративный proxy и CA](corporate-proxy.md).

Смена пароля в файле настроек не изменяет пароль уже созданной роли PostgreSQL. Изменение основной версии PostgreSQL требует отдельной миграции; замены тега образа для этого недостаточно.

Рабочие файлы скачиваются через авторизованные маршруты Django. Прямую публикацию media через веб-сервер не настраивайте. Непрерывная работа расписания и копирования требует постоянно работающего сервера.
