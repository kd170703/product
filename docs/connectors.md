### А. Вклады

Адаптер `cbr_deposits` проверяет название показателя, исключение эскроу, единицу «млн руб.», лист «итого», единственную строку нужной территории и даты каждого столбца. Каждое число — **остаток на дату** заголовка. Дата запуска задания никогда не подставляется как дата показателя.

Конфигурация:

```json
{
  "indicator_code": "cbr_deposits_moscow",
  "territory": "Москва",
  "unit": "млн руб.",
  "sheet": "итого"
}
```

Код показателя нужно связать с паспортом соответствующего показателя в импортированном реестре. Другие валютные листы не складываются с «итого».

### Б. Карты: требуется решение владельца методики

В исходных материалах название показателя включает расчётные и кредитные карты. Однако значения реестра соответствуют **только кредитным**:

| Дата официального листа | Все карты, тыс. ед. (C39) | Расчётные (D39) | Кредитные (E39) |
|---|---:|---:|---:|
| На 01.01.2025 | 67766.722 | 54671.253 | 13095.469 |
| На 01.04.2026 | 74749.865 | 64543.345 | 10206.520 |

Это расхождение определения, а не ошибка округления. Кроме того, заголовок ЦБ говорит об эмитированных картах, а не об уникальных гражданах. До решения владельца адаптер блокирует загрузку. Для подтверждённого определения задаются:

```json
{
  "indicator_code": "код_согласованного_показателя",
  "territory": "Москва",
  "unit": "тыс. ед.",
  "definition_confirmed": true,
  "metric": "credit"
}
```

Допустимые `metric`: `total` — C, `debit` — D, `credit` — E. Выбор должен соответствовать паспорту показателя. Тестирование `credit` на сохранённых файлах не означает согласование владельцем. F/G — карты, с которыми совершались операции с начала года; эти столбцы данным адаптером не загружаются.

### В. Доходы

Нужна таблица **среднедушевых денежных доходов по субъектам**, а не реальных доходов, заработной платы или покупательной способности. На индексированной карточке Росстата найдена именно подходящая таблица. Файл `urov_10subg-nm.xlsx` — обнаруженный адрес-кандидат старой публикации; его актуальность не подтверждена, сервер возвращает 503. Он не задан как безусловно проверенный URL пилота.

При получении официального XLSX администратор сверяет название, Москву, рубли в месяц и периоды. Годовая средняя и каждый квартал задаются **отдельными** наблюдениями с разными `period_start`/`period_end`. Квартальные значения нельзя складывать в годовую среднюю. Ссылка страхования в строке доходов исходного реестра должна быть исправлена отдельным подтверждённым действием.

### Г. Социальные вычеты

Официальная страница выпуска `16637538` содержит отчёт **за 2025 год**, опубликованный 15.07.2026 в 17:05. Для Москвы ссылка «по субъекту» ведёт на:

[77_5DDK_20260101.xlsx](https://www.nalog.gov.ru/html/sites/www.new.nalog.ru/files/related_activities/statistics_and_analytics/forms/5ddk/2025/77_5DDK_20260101.xlsx).

Выпуск [16481402](https://www.nalog.gov.ru/rn77/related_activities/statistics_and_analytics/forms/5ddk/16481402/) — за 2024 год, публикация 31.10.2025 15:08; файл — `2024/77_5DDK_20250101.xlsx`. Год в названии выпуска, дата состояния в имени файла и дата публикации — разные поля. Нельзя создавать наблюдение «2026 год» из-за публикации в 2026 году.

После получения файла нужно подтвердить строку **числа налогоплательщиков, заявивших социальные вычеты**, и графу общего количества. Нельзя подменять её суммой вычетов либо суммировать пересекающиеся категории налогоплательщиков. Адаптер не угадывает код строки и графу по недоступному файлу.

## Импорт сохранённого файла и настройка сопоставления

`parse_file(path, adapter, config)` используется и после сетевой загрузки, и для загрузки сохранённого файла. Поддержаны `xlsx`, `csv`, `json`, специальные `cbr_deposits` и `cbr_cards`; для недоступных Росстата/ФНС используются те же явные XLSX-сопоставления с подтверждением структуры.

Для проверенного пользователем нестандартного XLSX можно задать отдельные ячейки. **Адреса ниже — только пример настройки, не фактические адреса ФНС/Росстата**:

```json
{
  "indicator_code": "код_паспорта",
  "territory": "Москва",
  "unit": "руб./мес.",
  "structure_confirmed": true,
  "expected_markers": [
    {"sheet": "Данные", "cell": "A1", "text": "Среднедушевые"},
    {"sheet": "Данные", "cell": "A10", "text": "Москва"}
  ],
  "cells": [
    {
      "sheet": "Данные",
      "value_cell": "F10",
      "header_cell": "F3",
      "expected_header": "2025",
      "period_start": "2025-01-01",
      "period_end": "2025-12-31",
      "period_kind": "flow",
      "period_label": "2025 год"
    },
    {
      "sheet": "Данные",
      "value_cell": "G10",
      "header_cell": "G3",
      "expected_header": "I квартал 2026",
      "period_start": "2026-01-01",
      "period_end": "2026-03-31",
      "period_kind": "flow",
      "period_label": "I квартал 2026"
    }
  ]
}
```

Изменение контрольного текста блокирует файл. Маркеры должны проверять единицы и территорию, а не только название листа. `structure_confirmed=true` — явное подтверждение настройки администратором; оно не делает несуществующую проверку официального файла выполненной.

Для плоской таблицы используйте `fields`: имена полей приложения → имена столбцов файла. Поддержаны `indicator_code`, `value`, `unit`, `territory`, `period_start`, `period_end`, `period_kind`, `period_label`, `group`, `answer`, `question_version`, `numerator`, `denominator`, `data_state`. Неизменные поля можно задавать на верхнем уровне настроек. Для XLSX есть `sheet` и `header_row`, CSV — `delimiter`/`encoding`, JSON — `records_key`.

```json
{
  "indicator_code": "код_паспорта",
  "territory": "Москва",
  "unit": "чел.",
  "fields": {"value": "Количество", "period_start": "Начало", "period_end": "Конец"},
  "period_kind": "flow"
}
```

Значения/даты проверяются, дубли измерений внутри файла блокируются, разные территории/единицы в одном привязанном источнике не принимаются. Для нуля сохраняется `value="0"`, пропуска — `data_state="missing"`, неприменимости — `data_state="na"`. Проценты не превращаются в придуманные точные числители.

`discover(source)` ищет новые ссылки по `publications_url`. JSON-настройка `link_pattern` позволяет уточнить правило; `direct_only=true` использует только указанный файл. Нестандартная API-схема, HTML-таблица, авторизация, динамический сайт или XLS старого формата требуют нового адаптера либо предварительного сохранения XLSX. Папку внутренних выгрузок читает фоновый процесс приложения; она не сканируется сетевым адаптером.

## Защита загрузок и проверка

Сетевой загрузчик разрешает HTTP(S) без паролей в URL, только публичные IP и порты 80/443. Перед каждым перенаправлением адрес повторно проверяется; запрещены localhost, частные и служебные сети. Ограничения: 25 МиБ на файл, 25 секунд на HTTP-запрос, 5 перенаправлений, 50 000 строк, 120 МиБ распакованного XLSX. Используются штатные настройки прокси и проверки TLS. Для рабочей установки администратор дополнительно ограничивает исходящую сеть разрешёнными ведомствами.

В `tests/test_adapters.py` проверяются синтетическими файлами: ноль/пропуск/неприменимость, периоды, дубли, единицы/территории, числители/знаменатели, выбранная графа карт, блок несогласованного определения, структурные изменения, сопоставление сохранённого XLSX и запрет приватных адресов. Эти тесты не заявляют реальную загрузку Росстата/ФНС.

```powershell
docker compose exec web python -m unittest discover -s tests -p test_adapters.py -v
```

Реальные сетевые пробы и чтение официальных файлов Банка России выполнялись отдельно. Общая корректность записи версий, ручных поправок и расписания проверяется интеграционными тестами приложения.
